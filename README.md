### Что я обнаружила про сравнении IL

В ILSpy я увидела следующие отличия (Add(int a, int b)):

- В Debug присутствуют интрукции nop, которых нет в Release.

- В Debug объявлена секция local init с двумя переменными (result и int32). В Release этой секции нет и компилятор посчитал результат напрямую.

- В Debug результат последовательно сохраняется и считывается из локальных переменных: stloc.0, idloc.0, stloc.1, idloc.1. В Release эти операции отсутствуют.

- В Debug есть инструкция br.s IL_0009, которая передает управление на следующую инструкцию. В Release она не нужна и убрана.

- В методе Add() количество инструкций изменилось с 10 (Debug) до 4 (Release).

- В Debug размер кода метода - 11 байт, а в Release - 4 байта.


## Ответы на контрольные вопросы

1. Что такое IL и зачем он нужен между C# и машинным кодом?  

IL - промежуточный код, который получается после компиляции C#. он хранится в сборке вместе с метаданными и не привязан к конкретному процессору. IL нужен, чтобы отделить исхдный код от архитектуры, при запуске JIT-компилятор преобразует IL в машинные инструкции для нужного процессора и может применять оптимизации под него.

2.  Почему .dll можно декомпилировать?  

Сборка .NET содержит IL и метаданные, поэтому инструменты, например, ILSpy восстанавлиявают код, близкий к исходному. Сам факт компиляции в .dll или .exe не защищает код от просмотра.

3.  Какие отличия Debug и Release вы увидели в IL?  

В Debug сть инструкции , лишние локальные переменные (), промежуточные и  на следующую строку - в Release их нет. Компилятор устранил промежуточные операции, и IL стал короче.

4.  Почему Release обычно быстрее Debug?  

Release применяется больше оптимизаций: компилятор убирает лишние промежуточные операции, а JIT дополнительно оптимизирует код. Debug ориентирован на откладку, а не на скорость. Однако Release не гарантирует ускорения, результат зависит от кода, версии .NET и процессора, поэтому измеряют экспериментально.

5.  Почему строковый пароль в .dll нельзя считать защищённым? 

Строковые литералы хранятся в .dll как текст в UTF-16 без шифрования, в достаточно узнаваемом виде. Компиляция не скрывает секреты - их можно найти в HEX-редакторе или декомпиляторе.
